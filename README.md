# 一方小院 · Sprout Garden

一个适合手机和电脑的家庭种植日记。记录植物从种下到收获的过程，安排水分检查与施肥提醒，把小小的生长留在日常里。

使用原生 HTML、CSS 和 JavaScript ES modules 构建，无运行时依赖、账户系统或后端服务。

## 功能

- 植物档案：名字、种类、位置、种植方式、容器、排水、阶段、照片和备注。
- 待种清单、正在生长、归档状态，以及搜索与分类筛选。
- 生长日记：照片、株高、采收重量、浇水、施肥、修剪、换盆、病虫观察和阶段变化。
- 照护待办：到期提醒、延后、跳过和完成记录；完成后自动安排下次检查。
- 日历：查看近期照护，导出未来 30 天的 `.ics`，供手机或电脑日历导入。
- 草莓、空心菜、青椒、小番茄、生菜与自定义植物；指南附一般种植参考来源。
- JSON 完整备份与恢复，包括照片、日记和设置。
- 离线缓存、响应式导航、原生弹窗与键盘操作。

首次打开只提供草莓、空心菜、青椒、小番茄四个**待种模板**，没有虚构生长记录、历史浇水或收获。开始种植后才生成照护事项。施肥默认关闭，水分检查周期可以调整。

## 本地运行

需要 Node.js 22 或更新版本。不需要执行 `npm install`。

```sh
npm run dev
```

打开终端显示的 `http://127.0.0.1:4173`。更换端口可使用 `PORT=4174 npm run dev`。开发服务器仅监听本机回环地址；不能直接用该地址让另一部手机访问。

```sh
npm run check
npm test
npm run build
```

构建产物位于 `dist/`，可部署到静态 HTTPS 主机。请通过 HTTP/HTTPS 打开，直接双击 `index.html` 不适合 ES modules、数据库及 Service Worker 的使用方式。

## 数据保存与换设备

植物、照片和日记保存在当前网站来源下的浏览器 **IndexedDB**。刷新网页会保留记录，但手机、电脑、不同浏览器和不同网站地址各自保存，**不会自动同步**。

在“花园设置”导出 JSON 备份，再到另一台设备导入，即可迁移。导入会先校验，展示数量并要求确认，然后整体替换当前花园；不会合并两个花园。恢复前建议先导出当前记录。导出文件包含你的照片和文字，请保存在私人位置。

清除网站数据、卸载浏览器或系统回收存储可能删除本地记录。无痕模式和存储权限限制也可能导致保存失败。应用会明确显示失败，不会把失败的写入显示为成功，也不会静默清空旧数据。

多标签页可接收更新提示。保存时另有数据库版本检查：如果另一页已写入更新，旧页的保存会被拒绝，防止覆盖新记录。保留尚未保存的文字后刷新，再重新填写；本版本不自动合并并发编辑。

## 提醒的实际工作方式

网页通知需要浏览器授权，并依赖网页仍在运行。浏览器休眠、后台节流、关闭网页或系统限制都会影响检查；**它不是后台定时推送服务**。

希望关闭网页后仍收到提醒，可导出 `.ics` 并导入系统日历，同时允许该日历通知。导出使用设置中的日历提醒时间和导入设备的当地时间；日历事件附有提前 15 分钟的提醒，实际通知行为由日历应用决定。

`.ics` 是导出时的固定 30 天计划，**不是实时订阅**。在网站完成照护、改频率、归档植物后，已导入的系统日历不会自动更新。请删除旧导入计划并重新导出；建议导入到专用日历，便于替换。

浇水事项是观察提示。请根据植物、介质与实际湿度决定是否浇水；应用没有天气服务、湿度传感器或自动灌溉，也不会根据记录的光照时长自动推算用水量。

## 限制与验证

- 单个花园最多 500 株植物、20,000 条记录；格式化导出的完整 JSON 最大 60 MiB，写入时也会检查这个上限，保证可重新导入。
- 上传支持 JPEG、PNG、WebP，原图最多 20 MiB。界面会在本机压缩为最长边 1200 px 的 JPEG；备份校验限制每张图片解码后不超过 2 MiB。
- 备份会拒绝未知字段、重复 ID、关联不到植物的日记、非法日期/数值、外链图片与 SVG 数据。导入校验失败不会替换原数据。
- 日期计算按日历日处理，自动测试覆盖跨年、闰年、悉尼夏令时边界、提醒重复操作、备份拒绝与日历文本转义。
- 本次发布前已在 Node.js 22 下通过语法检查、17 项自动测试与静态构建。当前分支发布不会自动运行这些检查，后续修改请先运行上述命令。
- 离线缓存须先在线成功访问一次。字体使用 Google Fonts，无法联网时使用系统字体；个人记录和照片不会发送给字体服务。
- 使用现代浏览器的 IndexedDB、原生 `<dialog>`、图片解码与 Service Worker API。安装入口、系统通知和日历导入的表现取决于浏览器与设备；自动测试不等于所有手机系统的兼容性保证。

## GitHub Pages

当前使用原生分支发布：**Settings → Pages → Source → Deploy from a branch**，选择 `main` 分支、`/ (root)`。项目无需构建也可运行，`.nojekyll` 保证静态文件原样提供。每次推送 `main`，GitHub 自动更新网站。

- 在线网站：https://liqianyouy.github.io/sprout-garden/
- 源码仓库：https://github.com/LiqianYOUY/sprout-garden

`docs/pages-workflow.yml` 是可选的 Actions 工作流模板，当前不会触发。需要自动检查、构建后发布时，将它移到 `.github/workflows/pages.yml`，并把 Pages Source 改为 GitHub Actions；上传工作流的令牌需有 `workflow` 权限。模板使用 Node.js 22，检查、测试、构建成功后上传 `dist/`，PR 只检查不部署。

资源使用相对路径，支持 GitHub Pages 项目子目录。参考：[GitHub 官方 Pages 文档](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

## 仓库与隐私

仓库包含应用代码、通用种植模板与界面插画。私人 ChatGPT 聊天记录、真实植物照片、浏览器数据库、导出的 JSON 备份均不属于源码，也不应提交到 Git。初始模板不预填个人种植事实。

当前版本没有上传个人日记或照片的接口。公开部署公开的是应用代码，不会把某个浏览器里的花园记录公开。若以后添加账号和云同步，需要另外设计认证、访问权限与数据迁移。
