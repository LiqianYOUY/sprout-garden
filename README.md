# 一方小院 · Sprout Garden

适合手机和电脑的家庭种植记录网站，可管理植物、写生长日记、设置浇水和施肥提醒。

使用原生 HTML、CSS 和 JavaScript ES modules 构建，数据保存在浏览器中。

## 功能

- 植物档案：名称、种类、位置、种植方式、容器、排水、生长阶段、照片和备注。
- 待种清单、在种植物、归档记录，支持搜索和分类筛选。
- 生长日记：照片、株高、采收重量，以及浇水、施肥、修剪、换盆、虫害和阶段记录。
- 浇水与施肥提醒：完成、延后或跳过；完成后安排下次提醒。
- 日历：查看待办，导出未来 30 天的 `.ics` 计划。
- 草莓、空心菜、青椒、小番茄和生菜指南，附参考来源；也可添加其他植物。
- JSON 备份与恢复，包含照片、日记和设置。
- 手机与电脑布局、离线缓存、键盘操作。

首次打开会添加草莓、空心菜、青椒、小番茄四项待种计划。开始种植后启用浇水检查，周期可调整；施肥提醒默认关闭。

## 本地运行

需要 Node.js 22 或更新版本。不需要执行 `npm install`。

```sh
npm run dev
```

在本机浏览器打开 `http://127.0.0.1:4173`。更换端口使用 `PORT=4174 npm run dev`。

检查、测试与构建：

```sh
npm run check
npm test
npm run build
```

构建产物位于 `dist/`，可部署到静态 HTTPS 主机。本地开发请使用上述服务器打开。

## 数据保存与换设备

植物、照片和日记保存在当前网站的浏览器 IndexedDB 中。手机、电脑和不同浏览器分别保存，**不会自动同步**。

在“花园设置”导出 JSON 备份，再到另一台设备导入即可迁移。导入时会校验文件并显示记录数量；确认后**替换当前花园**。需要保留当前记录时，先导出备份。

清除网站数据、卸载浏览器或系统回收存储可能删除本地记录，请定期备份。保存失败时页面会显示提示。

同时打开多个标签页时，另一页的修改会触发更新提示。先保留未保存的文字，再刷新页面继续编辑。

## 提醒

网页通知需要浏览器授权，且网页保持运行。关闭网页后，可通过系统日历接收提醒。

在设置中导出 `.ics`，导入手机或电脑日历并开启日历通知。事件按设置中的时间和导入设备的当地时区安排，提前 15 分钟提醒。

`.ics` 保存导出时的固定 30 天计划。网站上的完成记录、频率调整和植物归档不会更新已导入的日历。计划变更后，删除旧计划并重新导入；使用单独的日历方便替换。

浇水前检查盆土湿度，提醒周期可在植物档案中调整。

## 文件与浏览器支持

- 单个花园最多 500 株植物、20,000 条记录，完整 JSON 备份最大 60 MiB。
- 照片支持 JPEG、PNG、WebP，原图最多 20 MiB；在本机压缩为最长边 1200 px 的 JPEG。备份中单张图片解码后最大 2 MiB。
- 导入校验包含字段、ID、日记关联、日期、数值和图片格式，校验通过后才能导入。
- 在线访问一次后可使用离线缓存。字体来自 Google Fonts，离线时使用系统字体。
- 需要支持 IndexedDB、`<dialog>` 和 Service Worker 的现代浏览器。系统通知、安装入口和日历导入由浏览器及设备支持。
- 测试覆盖跨年、闰年、悉尼夏令时边界、提醒重复操作、备份校验和日历文本转义。发布前运行检查、测试和构建命令。

## GitHub Pages

当前通过分支发布：**Settings → Pages → Source → Deploy from a branch**，选择 `main` 分支、`/ (root)`。项目可直接运行，`.nojekyll` 保留静态文件。推送 `main` 后，GitHub 自动更新网站；此方式不会自动运行检查和测试。

- 在线网站：https://liqianyouy.github.io/sprout-garden/
- 源码仓库：https://github.com/LiqianYOUY/sprout-garden

如需使用 GitHub Actions 自动检查并构建发布，将 `docs/pages-workflow.yml` 移到 `.github/workflows/pages.yml`，并把 Pages Source 改为 GitHub Actions。上传工作流的令牌需有 `workflow` 权限。模板使用 Node.js 22，检查、测试、构建成功后上传 `dist/`，PR 只检查不部署。

资源使用相对路径，支持 GitHub Pages 项目子目录。参考：[GitHub 官方 Pages 文档](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。
